* Decision
DOCUMENTED 2026-08-12: use direct Pandoc Org input to EPUB 3, with deterministic prebuilt assets and an export-only Org compatibility preparation step, then validate with EPUBCheck 5.3.0 and repository-specific EPUB regression assertions.
* Primary-source evidence
- Pandoc User's Guide (retrieved 2026-08-12): https://pandoc.org/demo/example3.html
  - current guide documents modular readers/writers, explicit input/output formats, =--citeproc=, external bibliographies, math, linked media inclusion, EPUB 3 semantics, and accessibility metadata.
- Pandoc EPUB metadata (retrieved 2026-08-12): https://pandoc.org/demo/example33/11.1-epub-metadata.html
  - documents explicit =accessModes=, =accessModeSufficient=, =accessibilityHazards=, =accessibilityFeatures=, and =accessibilitySummary= metadata fields.
- Pandoc 3.10.1 Org reader source (retrieved 2026-08-12): https://github.com/jgm/pandoc/blob/3.10.1/src/Text/Pandoc/Readers/Org/DocumentTree.hs
  - =propertiesToAttr= chooses =CUSTOM_ID= before =ID= for the Header identifier and filters both special properties from ordinary key/value attributes. Therefore a post-reader Header filter cannot recover the losing =ID= when both are present.
- Org Manual, citations (retrieved 2026-08-12): https://orgmode.org/manual/Citations.html
  - Org 9.8 documents =#+bibliography:= and =[cite:@key]= authoring syntax.
- W3C EPUB Accessibility 1.1 (retrieved 2026-08-12): https://www.w3.org/TR/epub-a11y-11/
  - requires package accessibility discoverability metadata and defines the accessibility conformance baseline used by the fixture policy.
- W3C EPUBCheck releases (retrieved 2026-08-12): https://github.com/w3c/epubcheck/releases
  - 5.3.0 is identified upstream as the latest production-ready release and validates EPUB 3.3.
- Org-roam upstream repository (retrieved 2026-08-12): https://github.com/org-roam/org-roam
  - confirms Doom integration and the plain-text/project-directory model used by our scoped setup.
* Why this route
Pandoc is current, scriptable, reproducible in CI/Nix, accepts Org directly, and has a mature EPUB writer. It avoids making an unmaintained third-party Org EPUB exporter the critical path. Org remains canonical; Pandoc is the publication compiler, not the authoring format.
* Compatibility boundary
Pandoc's Org reader is not Emacs itself. Authoring-only constructs must be tested in the representative fixture before relying on them. Stable =:ID:= properties remain canonical in Org.

Before Pandoc reads a manuscript, =tools/prepare-org-for-pandoc= writes a temporary sibling copy. For every source =:ID:= it materializes an explicit XML-safe =org-id-<ID>= target. Same-document =id:= links are rewritten to those aliases; links to IDs not present in the current source are left unchanged. Existing Pandoc-generated heading identifiers and =:CUSTOM_ID:= values remain intact. Build scripts delete the temporary copy on exit and never mutate the canonical Org source.

The Lua filter is intentionally narrower: it handles Pandoc's Figure-level =alt= quirk, which is actually visible in the AST. It does not attempt to reconstruct an =ID= value that Pandoc 3.10.1 has already discarded.
* Feature acceptance fixture
The fixture proves headings, stable Org-ID aliases, same-document Org =id:= links, custom-anchor behavior, internal fragment resolution, source block, table, footnote, citation/bibliography, MathML equation output, deterministic SVG, PNG and JPEG media, ordinary image inclusion, meaningful alt text, captions, Unicode, explicit cover/accessibility metadata, and EPUBCheck conformance. =tools/check-pandoc-org-reader= asserts the pinned reader quirks consumed by the compatibility layer; =tools/check-epub-fixture= inspects the packaged OPF/XHTML for repository-specific regressions after the standards validator runs.

Detailed accessibility expectations and diagnostics live in [[file:epub-accessibility.org][epub-accessibility.org]].

This pass closes the Project 1 transitive Python *version-lock* gap without pretending that a version lock is stronger than it is.  The research harness remains book-local and does not own StarIntel runtime behavior.

The dependency contract has two intentionally different files:

- =requirements.txt= is the small human-maintained set of direct research dependencies.
- =requirements.lock= is the complete installed distribution set observed for the tested CPython/platform contract, including transitive dependencies.

The lock is tested under CPython 3.12.3 on Linux x86_64 in a fresh virtual environment.  CI installs every locked distribution with =--no-deps=, runs =pip check=, and then independently compares the direct pins, lock contents, and installed distributions with =verify_dependency_lock.py=.

* Why the old direct pins were not enough
Before this pass, Project 1 pinned =jsonschema=, =scikit-learn=, =matplotlib=, and =datasketch= but allowed pip to choose every transitive dependency anew.  That made top-level package selection repeatable while still allowing the numerical/runtime environment to drift under the same Git commit.

Python documents virtual environments as isolated, disposable environments that should be recreated rather than committed.  pip's repeatable-install guidance distinguishes pinning direct packages from pinning the complete dependency graph and specifically notes that installing a fully pinned set with =--no-deps= adds protection against dependency-resolution changes.  pip also documents that =pip freeze= reports what is installed; it is not itself a solver result or a lockfile format.  Those distinctions define this pass's boundary rather than marketing the generated snapshot as magic reproducibility.

* Lock verification contract
=verify_dependency_lock.py= is deliberately independent of pip's resolver.  It:

1. accepts only exact =name==version= pins in the direct and lock files;
2. normalizes Python distribution names so =_=, =-=, and =.= spellings cannot create accidental duplicates;
3. requires every direct pin to be present at the same version in the lock;
4. enumerates the live environment with =importlib.metadata=;
5. ignores pip itself because pip is installation tooling rather than a Project 1 research dependency;
6. fails on a missing, extra, or version-drifted installed distribution.

The CI environment is then built *from the lock* using =pip install --no-deps -r requirements.lock=.  =pip check= remains a second, metadata-level dependency-consistency check.

* Remaining hardening boundary
pip's hash-checking mode is stronger than version-only pinning because it constrains package artifacts as well as versions.  This pass does not add hashes.  If the book later needs a supply-chain/byte-identity claim rather than a controlled research-version claim, add an explicitly generated =--require-hashes= lock with platform-aware artifact policy and test that separate contract.

For the foundational Project 1 research claim needed now, the tested contract is narrower: exact CPython version + isolated environment + complete transitive version pins + resolver bypass + dependency-metadata check + independent environment equality check.

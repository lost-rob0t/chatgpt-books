* Fixture trust hierarchy
Project 1 should use three deliberately different fixture classes.

** Tier A -- canonical format/adapter fixtures
Purpose: deterministic parser/adapter/schema coverage.

Sources may include GLEIF's official API example and current-format sample artifacts.

Rules:
- label them =illustrative_fixture= when GLEIF says the content may not represent reality;
- never use illustrative contents to teach factual ownership or organizational claims;
- preserve the upstream file identity and retrieval provenance;
- validate emitted StarIntel documents against canonical StarIntel 0.9.

** Tier B -- frozen real public observations
Purpose: provenance, reproducibility and realistic data-quality exercises.

Examples include the already-frozen GLEIF self-record from pass 04 and future explicit real API/Golden-Copy snapshots.

Rules:
- freeze exact bytes;
- record retrieval timestamp, URI, licence, content hash and source version/context;
- distinguish observed source facts from transformations and derived labels;
- never silently refresh the fixture.

** Tier C -- deterministic synthetic controls
Purpose: leakage and failure-mode experiments where the expected causal structure is known.

Use synthetic records for controlled duplicate/entity/time leakage demonstrations rather than trying to infer experimental ground truth from mutable real-world data.

* Level 2 -> StarIntel mapping requirements
Before implementation, the adapter mapping must predeclare where each RR-CDF concept lands.

Required semantic preservation:
- child identity;
- parent identity;
- direct versus ultimate accounting-consolidation semantics;
- relationship type;
- relationship periods/dates when supplied;
- registration/reporting status;
- validation information;
- source/provenance identity;
- raw-source lineage sufficient to reconstruct which source relationship produced which StarIntel relation.

The canonical StarIntel =relation= document should carry graph semantics. GLEIF-specific fields that have no stable canonical StarIntel equivalent should remain in a namespaced extension/provenance structure rather than expanding the StarIntel schema inside this book.

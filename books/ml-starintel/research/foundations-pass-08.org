* Scope
Turn the leakage taxonomy from earlier passes into deterministic executable controls for Project 1. This pass is synthetic by design: factual Tier B GLEIF observations remain provenance/integration fixtures, while leakage ground truth belongs to Tier C where entity identity, time of feature availability, duplicates, and labels are known exactly.

* Research questions
1. How much can row-random splitting overstate performance when repeated observations from the same entity cross train/test boundaries?
2. Does a strict chronological split alone prevent future-information leakage, or must feature availability also be enforced at prediction time?
3. How much can exact and near-duplicate cross-split contamination inflate a text classifier's evaluation?
4. Which split and near-duplicate rules can be declared before measurement so the evaluation protocol is not tuned after seeing results?

* Primary/authoritative sources inspected
- scikit-learn 1.9 =GroupShuffleSplit=: randomized splits over caller-provided groups; =test_size= is a proportion/count of groups, not rows; integer =random_state= provides reproducibility.
- scikit-learn 1.9 =TimeSeriesSplit=: time-ordered evaluation exists specifically because ordinary CV can otherwise train on future data and evaluate on past data.
- scikit-learn common-pitfalls guidance: information unavailable at prediction time is leakage and produces overly optimistic estimates; splitting should happen before learned preprocessing and test rows must not participate in fitting.
- Kapoor and Narayanan, =Leakage and the Reproducibility Crisis in ML-based Science= / =Patterns= 2023: taxonomy and documented prevalence of leakage-induced reproducibility failures.
- Matplotlib 3.11 release documentation / PyPI record for deterministic plot generation in this research harness.

** Experiment A -- repeated-entity leakage
Synthetic corpus:
- 160 entities;
- 4 observations per entity;
- entity labels alternate deterministically between the two classes;
- each observation contains a stable entity-specific signature token plus neutral per-observation noise;
- no cross-entity predictive feature is intentionally supplied.

Splits:
1. =row_random=: =train_test_split(test_size=0.25, random_state=1729, stratify=y)=.
2. =entity_group=: =GroupShuffleSplit(n_splits=1, test_size=0.25, random_state=1729)= with =entity_id= as the group.

Predeclared invariant: =entity_group= must have zero entity IDs shared between train and test. =row_random= contamination is measured, not assumed.

Hypothesis: =row_random= will be substantially overoptimistic because the same entity signatures can occur in both partitions, while the grouped split requires generalization to unseen entity signatures. Status at protocol freeze: UNTESTED.

** Experiment B -- temporal and future-information leakage
Synthetic corpus:
- 24 monthly periods;
- 24 records per period;
- balanced binary labels;
- a deliberately imperfect stable signal is generated deterministically and is correct for 75% of records;
- =future_resolution= equals the target but has =available_at = observed_at + 7 days=.

Evaluations:
1. =random_finalized=: row-random split over the fully enriched/finalized table, including =future_resolution=.
2. =temporal_finalized=: strict cutoff after month 18; train months 1--18/test months 19--24, still incorrectly including =future_resolution=.
3. =temporal_point_in_time=: the identical temporal train/test indices, but feature extraction drops any field whose =available_at > prediction_at=, so =future_resolution= is unavailable.

Predeclared temporal invariant: =max(train.observed_at) < min(test.observed_at)=. The point-in-time feature builder must never emit =future_resolution= for these records.

Hypothesis: both finalized-table conditions can remain implausibly strong because chronological splitting alone cannot undo a feature that already contains future knowledge; the point-in-time condition should reveal the weaker true signal. Status at protocol freeze: UNTESTED.

** Experiment C -- exact and near-duplicate leakage
Synthetic corpus:
- 160 base records, balanced labels;
- each base record has three rows: original, exact duplicate, and deterministic near-duplicate;
- variants share a base-specific token and semantic content; the near-duplicate changes one low-information token.

Predeclared duplicate algorithm:
1. normalize text by Unicode case-folding, replacing non-alphanumeric runs with one space, collapsing whitespace, and trimming;
2. exact duplicate identity is SHA-256 of normalized UTF-8 text;
3. near-duplicate similarity is Jaccard similarity over the set of normalized whitespace tokens;
4. create an undirected edge for similarity >= =0.80=;
5. near-duplicate clusters are deterministic connected components of this threshold graph; component IDs are the lexicographically smallest record ID in the component.

No threshold search, model-based embedding similarity, or post-result tuning is allowed in this pass.

Splits:
1. =row_random=: =train_test_split(test_size=0.25, random_state=1729, stratify=y)=.
2. =duplicate_cluster=: =GroupShuffleSplit(n_splits=1, test_size=0.25, random_state=1729)= using the frozen near-duplicate component ID as group.

Predeclared invariants: the cluster split must have zero exact hashes and zero near-duplicate component IDs shared between train/test. Row-random exact/near contamination rates are measured.

Hypothesis: row-random evaluation will be inflated by cross-split copies/near-copies; cluster-group evaluation will require generalization to unseen base records and score materially lower. Status at protocol freeze: UNTESTED.

** Experiment A -- TESTED
| Split | Balanced accuracy | Accuracy | Test rows | Entity overlap | Test-row entity contamination |
| row random | 0.975 | 0.975 | 160 | 134 entities | 0.95 |
| entity group | 0.500 | 0.500 | 160 | 0 entities | 0.00 |

Observed delta in balanced accuracy: =+0.475= for row-random evaluation relative to the entity-group split on this deterministic control.

Interpretation: the row-random condition overwhelmingly placed test observations from already-seen entities into training. The classifier could exploit the stable entity signatures. The grouped split removed that path and performance fell to chance on this deliberately no-cross-entity-signal corpus. This confirms the predeclared hypothesis for this fixture only; it is not a production StarIntel performance estimate.

** Experiment B -- TESTED
| Evaluation | Balanced accuracy | Accuracy | Temporal ordering |
| random finalized | 1.000 | 1.000 | not the controlled temporal split |
| temporal finalized | 1.000 | 1.000 | train strictly before test |
| temporal point-in-time | 0.750 | 0.750 | train strictly before test |

The temporal invariant passed: all training observations preceded all test observations. The point-in-time builder emitted zero =future_resolution= features. Yet the =temporal_finalized= condition still scored 1.000 because the finalized table already contained the target-equivalent future field.

Interpretation: strict chronological splitting is necessary but not sufficient when feature construction itself violates point-in-time availability. On this control, removing the future-only field exposed the deliberately 75%-accurate stable signal exactly as designed.

** Experiment C -- TESTED
The frozen Jaccard threshold remained =0.80=; no threshold search occurred after results were observed. The deterministic fixture produced 160 near-duplicate components for 160 base records.

| Split | Balanced accuracy | Accuracy | Exact test contamination | Near-component test contamination | Exact hash overlap | Near-component overlap |
| row random | 0.9583333333 | 0.9583333333 | 0.50 | 0.925 | 50 | 111 |
| duplicate cluster | 0.500 | 0.500 | 0.00 | 0.00 | 0 | 0 |

Observed balanced-accuracy delta: approximately =+0.4583= for row-random evaluation relative to the duplicate-cluster split.

Interpretation: copies and near-copies crossed the naive split at very high rates and allowed a model with no intended cross-base predictive signal to appear strong. Grouping the frozen duplicate components removed both exact and near contamination and returned performance to chance on this controlled corpus.

* Implementation implications
1. Project 1 must make the split unit explicit. Row-level random splitting is not an acceptable default when multiple rows can represent the same real entity.
2. Every feature needs an availability-time contract for temporal evaluation. A chronological split cannot rescue a finalized/enriched table containing future knowledge.
3. Exact and near-duplicate grouping must occur before train/test assignment when duplicated source material can cross records.
4. Duplicate-cluster construction and thresholds belong in the dataset-build manifest/provenance so evaluation can be reproduced.
5. Learned preprocessing remains train-only. No vocabulary/statistic fitting may see test records.
6. Tier C controls are teaching/verification fixtures. Tier B factual data remains separate and should not be given synthetic ground-truth semantics.

* Remaining uncertainty
- Whether real Book 1 datasets need MinHash/LSH or embedding-assisted candidate generation for near-duplicate candidate search; the O(n^2) Tier C fixture is intentionally inspectable, not scalable.
- How entity grouping, duplicate grouping, source lineage and time should compose when several constraints apply simultaneously to real records.
- Which real-data task should be the first non-synthetic evaluation after the deterministic controls.
- Broader cross-language StarIntel conformance and the final transitive dependency lock remain separate work.

* Next research slice
The basic leakage hypotheses are no longer blockers. The next highest-value question is how to compile multiple leakage constraints into one deterministic split policy for real StarIntel-style datasets: entity identity, duplicate component, source/document lineage, graph-connected groups when appropriate, and temporal cutoff/feature availability. Research and specify that composite split planner before Project 1 implementation hardens its dataset manifest format. Then add a non-synthetic dry run that diagnoses contamination without pretending the tiny factual GLEIF fixture is large enough for meaningful model evaluation.

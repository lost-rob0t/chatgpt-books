#+title: Project 1 -- Foundational Research Harness

* Purpose
This is an executable research harness for Project 1, not chapter prose and not a replacement StarIntel runtime.

It currently exercises:
- Experiment E: a pinned StarIntel 0.9 wire-schema conformance smoke matrix.
- Experiment D0: a narrow synthetic provenance-manifest round trip used to verify the harness shape.
- Experiment D1: a frozen official GLEIF public-source extract mapped into a canonical StarIntel =org= record with byte hashes and provenance reconstruction checks.
- D2A: official GLEIF current-format sample =org= + =relation= adapter-shape coverage, including honest unresolved endpoints where the sample bundle lacks matching Level 1 records.
- Experiment D: a frozen factual as-of primary GLEIF API snapshot mapped offline into three entity-closed =org= documents and two =relation= documents with source/hash provenance reconstruction.
- Experiments A--C: deterministic synthetic leakage controls for repeated entities, point-in-time availability, and exact/near-duplicate contamination.
- Composite split planning: deterministic hard must-link closure plus temporal/feature admissibility and task-specific graph grouping.
- Pass-12 scalable duplicate candidates: exact hashes + deterministic blocking + MinHash/LSH candidates, followed by exact normalized token-Jaccard verification before component closure.
- Pass-14 environment reproduction: exact CPython selection, an isolated virtual environment, complete transitive version pins, resolver bypass, metadata consistency checks, and an independent installed-environment equality check.

Current version language is intentionally split: =starintel-server/schema/starintel-schema.lock.json= reports =release_version="0.9.1"= while the wire/base family remains =schema_version="0.9.0"=. These fixtures therefore correctly retain =schema_version: "0.9.0"=; that must not be described as the current release/profile being 0.9.0. The separate top-level document =version= is integer =1= in the research fixtures.

* Scalable candidate boundary
=near_duplicate_candidates.py= is a dataset-preparation component, not a search service. It proposes canonical record-ID pairs from:
- exact normalized-text hashes;
- a deterministic rare-token blocker;
- =datasketch==2.0.0= MinHash/LSH with explicit =affine32= scheme, seed, permutation count and threshold.

Candidate provenance is retained. Every candidate is then exact-Jaccard verified before an edge can enter duplicate-component closure. Approximate retrieval never defines duplicate truth.

Pass 12 TESTED this path on Tier C: 526 candidate pairs versus 114,960 all pairs, all 480 exact qualifying pairs proposed, 46 candidate false positives safely rejected by exact verification, final components identical to the all-pairs oracle, and deterministic output under the tested permutations. Larger-public-corpus recall/runtime remains UNTESTED.

* Dependency boundary
=requirements.txt= is the deliberately small human-maintained list of direct dependencies. It is not the reproducible environment contract.

=requirements.lock= is the complete transitive *version* lock for the tested Project 1 environment. CI creates a fresh CPython 3.12.3 virtual environment, installs every locked distribution with =--no-deps=, runs =pip check=, then runs =verify_dependency_lock.py=. The verifier fails if a direct pin is missing or changed, if the environment has an extra or missing distribution, or if any installed version differs from the lock.

The tested environment contract is intentionally narrower than a cryptographic artifact lock:
- TESTED platform/interpreter: Linux x86_64 + CPython 3.12.3;
- lock scope: Project 1 Python research dependencies, excluding pip itself;
- NOT CLAIMED: cross-platform wheel identity or byte-identical package artifacts;
- NOT IMPLEMENTED: pip =--require-hashes= artifact locking.

See =research/foundations-pass-14.org= for the resolver capture, complete observed package set, primary documentation, and claim boundaries.

* Claim-status rules
- A CI invocation that actually executes a case may be recorded as TESTED.
- A failing invocation is FAILED and remains part of the research record.
- D0 does not prove public-source provenance.
- D1 proves only the earlier frozen contact-page extract path.
- D2A proves the Tier A adapter shape and unresolved-endpoint semantics, not current factual relationships.
- Full D proves reproducibility and canonical validation for the frozen Tier B as-of observation; it does not claim those relationships persist forever.
- A--C prove only the specified deterministic synthetic leakage controls.
- The pass-12 candidate result proves contract behavior only on the frozen Tier C oracle fixture. It does not prove production recall/runtime.
- The pass-14 dependency result proves a complete version-pinned environment only for its tested Python/platform contract; it does not prove package-artifact identity or cross-platform equivalence.
- Cross-language Python/Nim/Common Lisp conformance remains UNTESTED here.

* First observed failure
The first CI execution on 2026-08-14 rejected the supposed-valid fixture because top-level StarIntel =version= is an integer with minimum 1, not the schema-version string. The harness was corrected to =version: 1= and retains the original mistake as a negative regression case. This is exactly why implementation claims stay UNTESTED until exercised against the canonical schema.

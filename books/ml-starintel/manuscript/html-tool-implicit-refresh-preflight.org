* Why this matters
A gold tool trace is a sequence of explicit actions: =select=, =extract=,
and typed =follow=. A page can also contain metadata requesting an *automatic*
refresh or redirect. That transition is not represented by any action in our
bounded offline executor. Pretending the page is inert creates a misleading
gold label: a tool trace may appear correct only because the simulator omitted
an implicit navigation.

The laboratory chooses a deliberately narrow contract. It does not implement
meta-refresh timing, browser execution, network requests, JavaScript or a new
tool. Instead it rejects an active =<meta http-equiv="refresh">= declaration
with the existing =unsafe_navigation= failure. A same-origin refresh is still
implicit, so it is rejected too. This is a *course-local oracle policy*, not a
claim that our bounded parser behaves like a browser in other respects.

* Source boundary
The maintained source is
=file:../code/html-tool-benchmark/offline_html_trace_executor.py=. The shared
=_preflight_parsed_pages= function parses every supplied fixture page *before*
the first trace action runs, including pages no gold trace visits. The new
preflight walk inspects parsed elements without re-parsing or making network
calls. Attribute names are already lowercased by the standard-library HTML
parser. An =http-equiv= value is compared after trimming surrounding whitespace
and applying case-insensitive normalization. If it equals =refresh=, preflight
rejects the fixture. Lack of =content= does not make an active declaration
eligible: the synthetic contract errs on rejecting ambiguous automatic control.

The walk skips descendants of =template=, =script=, and =style=: they do not
contribute active metadata to this oracle. Ordinary =meta= elements such as
=content-type=, =name= or the benchmark's =data-bk08= decoration remain valid.
Duplicate =http-equiv= attributes continue to take the existing =parse_bounds=
route rather than silently picking one value.

* Minimal RED example
#+begin_src python :eval never
from offline_html_trace_executor import _preflight_parsed_pages

pages = {
    "/start.html": "<p id='label'>Ada</p>",
    "/unvisited.html": '<meta http-equiv="REFRESH" content="0;url=/next.html">',
}
_preflight_parsed_pages(pages)  # TraceFailure(code="unsafe_navigation")
#+end_src

Before the correction, the parser accepted that inventory even though it was
not representable by an explicit navigation trace. After the correction, a
single unsupported refresh makes the entire fixture unsuitable for scoring.
The result does not depend on which page the trace initially opens.

* Positive controls
#+begin_src python :eval never
_preflight_parsed_pages({
    "/ok.html": '<meta data-bk08="head_variant_0"><p>Ada</p>',
    "/inert.html": '<template><meta http-equiv="refresh" content="0"></template>',
})  # succeeds: ordinary metadata and inert template subtree
#+end_src

The behavior is intentionally not a catch-all ban on =<meta>=, nor a policy
about a string containing the word =refresh=. Only the active parsed element
with a qualifying =http-equiv= attribute triggers the typed failure.

* Problem: a self-consistent gold trace can use ambiguous HTML

BK08 evaluates traces against deliberately bounded *offline static HTML*.
The same parser executes gold and candidate traces. Agreement between them
is therefore not proof that the HTML reference itself is unambiguous.

Consider one anchor with two =href= attributes:

#+begin_src html
<a id="record" href="/approved.html" href="/alternate.html">Open</a>
#+end_src

The old parser silently preserved the first =href=. A gold trace could
therefore visit =/approved.html= and pass, even though the input contains
conflicting navigation instructions. Other tooling might choose a different
error-recovery interpretation. BK08 should not present such a record as a
well-defined gold fixture.

* Bounded attribute contract

The offline parser now rejects *any repeated attribute name on the same
HTML element*, including repetitions with equal values. Attribute names
arrive normalized to lowercase from Python's =HTMLParser=, so =href= and
=HREF= are duplicates. The error uses the existing typed =parse_bounds=
category. This is intentionally stricter than permissive browser parsing;
it does not assert the behavior of an arbitrary browser DOM.

Independent elements may still use the same =id=: selecting that identifier
remains a distinct =selector_ambiguous= error, not a duplicated attribute.
Distinct attributes on one element remain valid. The bounded parser parses
*all supplied pages before executing any trace*, so an unused page carrying
an ambiguous duplicate cannot evade validation.

#+begin_src python :results output :exports both
from offline_html_trace_executor import TraceFailure, run_trace

    run_trace(bad, '/index.html', [])

good = {'/index.html': '<p id="record" class="person">Ada</p>'}

#+begin_example

The reported failure occurs before gold or candidate scoring. It is not a
new success metric, selector feature, trained ranker, model, browser, or
networking implementation.

* Exercises

2. ★★ Change the second =href= to equal the first. Explain why the
   canonical offline-fixture policy still rejects the duplicate.

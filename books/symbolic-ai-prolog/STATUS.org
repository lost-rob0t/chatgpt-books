* Active worker draft -- Project 2 milestone B
- Issue #99 specifies Chapter 8 relational action-schema planning as the next dependency-ready slice after merged explicit search.
- Planning states are finite ground fact sets canonicalized before duplicate-state handling. This deliberately preserves Chapter 7's explicit state-identity contract.
- Operators are inert =schema(Id,Action,Preconditions,Add,Delete)= terms. The planner never executes the action or precondition terms as arbitrary host goals.
- Each applicability attempt uses =copy_term/2= to freshen schema variables, then shares ordinary Prolog bindings consistently across the copied precondition list.
- Only a ground concrete action and ground add/delete effects may cross the transition boundary. Unsafe schemas that leave output variables unconstrained are rejected rather than admitting nonground successor states.
- Successor construction subtracts only declared delete effects and unions declared add effects, preserving unrelated state facts. A synthetic field-service fixture carries ticket/topology/permission facts specifically so accidental state erasure is testable.
- Breadth-first forward state-space search returns =found(plan(Steps,States))= or explicit exhaustion; =step(SchemaId,ConcreteAction)= preserves operator identity separately from expansion diagnostics.
- Chapter 8 derives each mechanism, includes worked field-service planning, three failure labs, fifteen exercises, and editable/rendered =relational-planning-flow.dot/svg= assets.
- Research record 05 inspects Fikes/Nilsson 1971 plus current SWI =copy_term/2= and =sort/2=. The manuscript explicitly calls this a course-local STRIPS-style subset rather than claiming equivalence to the complete historical STRIPS system or PDDL.

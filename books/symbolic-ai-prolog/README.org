* Purpose
A serious independent technical book, eventually about 300--700 rendered EPUB pages when depth warrants it. It is not a README expansion or generic tutorial dump.
* Audience
Prolog learners ready to use logic programming for AI, planning, explanation, and knowledge representation.
* Prerequisites
Prolog fundamentals or completion of [[file:../prolog/README.org][Prolog for Beginners: Thinking in Relations]]. This book may recap a prerequisite while deriving a symbolic-AI mechanism, but the pure Prolog foundations remain owned by the beginner volume.
* Learning outcomes
The reader should be able to explain the core ideas, implement important mechanisms, debug failures, evaluate tradeoffs, and extend the systems built in the major projects.
* Scope boundary
This volume owns classical/general symbolic-AI mechanisms in Prolog: meta-interpretation, explicit search/control, planning, semantic knowledge representation, provenance, abduction, explanation, constraints, production/rule engines, and hybrid symbolic composition.

The standalone sibling [[file:../prolog-llms/README.org][Prolog + LLMs: Neuro-Symbolic Systems from First Principles]] owns the explicit LLM/neuro-symbolic/RLM arc. Cross-link shared symbolic foundations where useful, but keep the classical mechanisms here complete enough to stand on their own.
* Major projects
- [[id:feb3b263-3d59-562d-bc7b-487c3fdf432e][Meta-Interpreter]] -- Develop increasingly capable interpreters with tracing, control, and explanation.
- [[id:868dd81e-3d0d-5f7b-bd3c-83a9fba898df][Planner]] -- Model goals, states, and actions relationally and compare planning strategies.
- [[id:fad84457-f03e-5fa2-b513-d5e6a0e34475][Semantic Knowledge Graph]] -- Represent structured knowledge as relations with provenance and query APIs.
- [[id:20c5f8d9-0f29-50c2-b98d-5c887fdccc86][Abductive Explanation System]] -- Generate candidate explanations, assumptions, contradictions, and justification traces.
- [[id:72bc9870-0c97-572e-9c27-5c444141cfc6][Rule/Expert-System Engine]] -- Contrast native Prolog inference with an explicit production-system engine.
- [[id:dd7637af-b3a4-54bc-aba2-309412a1da1a][Hybrid Symbolic Reasoning System]] -- Capstone combining rules, constraints, planning, explanation, and controlled external integration.
* Current implementation slice
Project 1 is merged through milestone B. Milestone A established the closed rule-as-data meta-interpreter, proof/provenance trees, fresh rule invocation semantics, ordinary alternative-rule backtracking, path-local variant cycle detection, and the object-rule budget. Milestone B added the closed =either(Left,Right)= control form plus bounded =search_report/4= diagnostics for ground ordinary object goals, preserving failed matching-rule attempts and explicit =proved=/=cycle=/=exhausted= outcomes without pretending to reproduce SWI-Prolog's runtime debugger trace.

Project 2 milestones A and B are merged. Chapter 7 represents a finite ground transition graph as closed =edge(Action,From,To)= data, uses one explicit frontier loop for deterministic DFS and BFS, defines ground state identity/closed-set semantics, returns typed path-or-exhaustion data, and keeps state-expansion diagnostics separate from the selected path. Chapter 8 then derives a small STRIPS-style forward state-space planner from reusable =schema(Id,Action,Preconditions,Add,Delete)= data: schemas are freshened before relational precondition matching, only ground action/effect instances cross the transition boundary, explicit add/delete effects preserve unrelated facts, successor states are canonicalized before duplicate handling, and returned plan steps retain stable schema IDs plus concrete actions.

Project 2 milestone C is the active worker slice under issue #110 / PR #112. Chapter 9 keeps the Chapter 8 action/state semantics fixed and changes search policy explicitly: non-negative integer action costs, uniform-cost search over a min-priority heap, a ground-state best-known-=g= map with strict-improvement replacement, stale/dominated diagnostics, and A* as the same search kernel with =f = g + h=. Heuristics cross the boundary only as validated closed data (=zero= or a finite =table([estimate(State,H),...])=); the planner never executes caller-supplied heuristic goals and does not claim to prove heuristic admissibility or consistency. A weighted technical-recovery fixture makes fewest-actions versus least-cost planning, equal-cost domination, stale heap entries, zero-cost-cycle handling, and a deliberately bad-but-well-formed heuristic observable rather than rhetorical.

The same Chapter 9 draft now also derives caller-bounded depth-first search and bounded iterative deepening. Their public result algebra separates =found/1=, =cutoff/2=, and =exhausted/1= so a caller-imposed depth limit cannot be relabeled as logical exhaustion. The depth-first kernel uses path-local canonical-state cycle pruning rather than a global state-only visited set; iterative deepening records each limit and has its own explicit maximum depth instead of promising unbounded termination. Korf 1985 is used for the primary depth-cutoff/DFID lineage with its tree-search theorem scope kept distinct from the course planner's graph semantics.

Constraint integration, semantic knowledge graphs, abduction, production matching networks, and the hybrid symbolic capstone remain later work. Explicit LLM/neuro-symbolic/RLM integration remains in the sibling =prolog-llms= volume.

* Reader mastery gates
** Gate A -- Canonical data
The reader can read =core.star=, distinguish canonical =0.10.1= from historical compatibility, explain =id=/=rev=/=schemaVersion=/=dtype=/=dataset=, and build/validate one concrete document without inventing a parallel schema.

** Gate B -- Distributed ingest
The reader can trace one document across admission, publish, delivery, durable mutation, outbox/event and read-back, naming exactly what each observation proves and does not prove.

** Gate C -- Actors and work
The reader can trace one actor work item from target selection through registration/address resolution, typed envelope, send, handler receipt, failure, recovery and derived output without confusing actor targets with =investigation-target=.

** Gate D -- Investigation graph
The reader can start from a research question and connect =investigation-target=, =operation=, datasets, documents, relations, provenance, actors and query/search surfaces into one inspectable investigation.

** Gate E -- Extension
The reader can add a capability that consumes canonical contracts, declares its boundary, emits provenance-preserving results, has executable tests, and does not copy StarIntel runtime logic into the extension.

** Gate F -- Operations
The reader can debug a deliberately broken multi-service run from evidence/correlation IDs and can identify the first unproven boundary before changing code or restarting services.

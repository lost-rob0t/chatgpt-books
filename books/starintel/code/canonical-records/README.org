- 90 persistent / 33 transient manifest inventory and persistent-only discovery;
- person, org, and relation round trips and optional revision omission;
- local typed endpoint consistency;
- malformed identity, missing required fields, old aliases, unknown dtype and
  wrong version rejection;

- duplicate decoded keys rejected by the book-local original-text guard;
- a recorded duplicate-key limitation of the pinned SDK parser alone;
- one explicit legacy migration with original-payload preservation;
- semantic identity for an already-current input;
- accepted shape of a dangling reference, documenting the absence of storage
  referential checks at this boundary.

* Evidence boundary
The duplicate-key guard is book-local admission policy, not a patch to the SDK
or a claim about deployed servers. It does not impose transport resource limits.
No broker acknowledgement, persistence, actor execution, authorization, complete
historical migration coverage, or all-dtype conformance is proved by this suite.

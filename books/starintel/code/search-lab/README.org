#+title: Chapter 15 / Project 4 -- Pinned Search Lab

* Purpose and evidence boundary
This is a search client and inspection lab, not a local search engine.
Canonical fixtures use the same generated SDK authority as Project 1.
Historical runtime fixtures in the optional HTTP tier are explicitly different.

Hermetic local evidence: 23 Python tests and 15 Lisp scenario checks passed.
Python runs the real pinned JavaScript index under a capture callback and the
real canonical SDK. SBCL runs unchanged selected upstream parser/handler/scope
compiler/egress forms with dependency doubles declared in =hermetic.lisp=.
These checks do not prove credential authentication, HTTP middleware, Lucene
analysis, query containment, actual indexing, ranking or durable visibility.

The service runner performs actual HTTP requests and synthetic writes. It is
NOT part of hermetic discovery. Its assertions are UNTESTED in local authoring;
absence of a service is not a skip or a pass. Use it only in a dedicated stack.
No actor-failure or target-recovery experiment is duplicated from PR #136.

* Optional real service experiment
Provision a fresh local StarIntel stack at the server pin using its maintained
stack tooling. This lab deliberately does not copy Docker/Nix deployment logic.
Its prerequisite checklist is concrete:

1. Running StarIntel HTTP, RabbitMQ ingest, CouchDB and connected Clouseau.
2. Install =source/views/search.json= from this pin as =_design/search= in the
   configured default database. Confirm the installed body and =fts= index.
3. Public mode enabled; set =STAR_PUBLIC_SEARCH_DATASETS=book-public= before
   runtime configuration loads. A wildcard public list fails this experiment.
4. Provision four valid credentials in the server credential store. Supply them
   from a keyring or environment, never a checked-in configuration:

| Environment variable | Tenant | Required scopes |
|----------------------+--------+-----------------|
| =STAR_SEARCH_LAB_WRITER= | default | identity:read, documents:write, documents:read, dataset:book-public, dataset:book-private, tenant:default |
| =STAR_SEARCH_LAB_OTHER_WRITER= | other | identity:read, documents:write, documents:read, dataset:book-public, tenant:other |
| =STAR_SEARCH_LAB_READER= | default | identity:read, search:read, dataset:book-public, tenant:default |
| =STAR_SEARCH_LAB_NOSEARCH= | default | identity:read, dataset:book-public, tenant:default; deliberately no search:read |

Do not grant admin or wildcard dimensions to READER/NOSEARCH. Authentication
binding must match the declared tenants. The script first requires all four
credentials to succeed at =/auth/context=, then performs the search denials.
The current schema is historical =0.9.0= wire format; writes clone the existing
=code/records/fixtures/person.json= and assign a fresh per-run synthetic identity.
This is no claim that canonical 0.10.1 ingest migration has completed.

Set =STAR_SEARCH_LAB_URL= to an HTTP(S) loopback base URL without a path,
username/password or query, and =STAR_SEARCH_LAB_DISPOSABLE=1=. Then:

#+begin_src sh
python3 books/starintel/code/search-lab/service_checks.py --seed
#+end_src

The runner writes five synthetic records into =book-public=/=book-private=,
uses authenticated by-ID read-back with a 30-second deadline per record,
then separately polls exact search-visible sets with a 30-second deadline.
Three default-tenant public records allow one-row pagination; one private
record and one other-tenant public record are negative/positive scope controls.
The public set must contain four identities and the restricted reader set
three. It checks eleven actual HTTP denial/input cases and tenant egress.
A twelve-page budget, ten-second request timeout and response byte budget bound
the client. Search output is a sanitized JSON summary; credentials are never
included. Keep the stack quiescent and delete the entire disposable deployment
when finished; the script does not delete records from an existing corpus.

For a service failure experiment, stop only Clouseau in that isolated stack:

#+begin_src sh
python3 books/starintel/code/search-lab/service_checks.py --expect-backend-failure
#+end_src

This mode requires a 5xx response rather than a successful empty page. A
backend that maps its failure to 404 or another status needs an explicitly
reviewed assertion, not a fabricated pass. Restore the service manually.
No target recovery or actor failure is simulated.

* Bounded local index capture
The Node capture wrapper limits each synthetic document to 2,048 emitted index
field/value pairs. The ceiling belongs to this teaching harness, *not* to
CouchDB/Clouseau or the production StarIntel server. The exact pinned server
index function remains unchanged. A document that would exceed this budget
raises an error and produces no partial JSON output; this is a failed lab
observation, not evidence that the document is unindexable in production.

Run =python3 -m unittest test_emission_budget -v= from the search-lab directory
(or use the existing =run-tests= suite with its pinned dependencies). Boundary
tests accept exactly 2,048 emissions, reject 2,049, and preserve regular
small-document projections. The injected array is synthetic, not collected data.

** Chapter 10 -- Production Systems
Goal: derive a transparent production-system control loop from the existing directional matcher: ground working memory -> shared-binding multi-condition joins -> explicit activations -> deterministic agenda/conflict resolution -> firing -> exact-activation refraction -> retained justifications.
Dependencies: Symbolic Representation and Pattern Matching/Unification. Planning provides prior project context and evidence-discipline vocabulary, but production-rule semantics do not depend on planner action semantics.
Examples: a synthetic infrastructure-diagnosis chain with stable fact identities, activation tables, repeated-variable joins, salience/order/support tie-breaking, duplicate fact assertion, a no-op refraction case, and bounded non-quiescent inference.
Exercises: debug inconsistent joins, fact-reuse assumptions, agenda ordering, malformed/ungrounded action output, refraction loops, and =:BOUNDED= versus =:QUIESCENT=; extend the technical fixture without turning it into a production diagnosis claim; identify exactly which repeated work motivates incremental matching.
Visuals: editable working-memory -> match/join -> activation -> agenda -> fire/assert/justify cycle plus support/justification traces.
Expected code: Project 4's full-rematch teaching engine with ground facts and stable fact IDs, matcher reuse, multi-condition joins, inspectable activations, deterministic agenda order, exact-support refraction, trusted actions returning validated symbolic fact data, explicit bounded termination, and justification records.
Research: Davis and King 1975 for production-system framing; Forgy 1981/1982 for OPS5/RETE lineage and the repeated matching problem; current CLIPS 6.4.2 documentation for maintained activation/agenda/salience terminology. This chapter does not claim OPS5/CLIPS conformance, RETE/TREAT implementation, truth maintenance, persistence, concurrency, or performance results; those deeper engine mechanisms remain in =books/expert-systems=.

Research: authoritative logic/formal-methods sources; do not infer semantic soundness merely from a checker accepting its own syntax.

* Purpose
This directory is the executable Project 1 system from [[file:../../PROJECTS.org][PROJECTS.org]]. It grows with the book; later chapters extend this system rather than replacing it with disconnected syntax demos.

The dataset is synthetic and intentionally small enough to inspect by eye.

* Files
- =community.pl= :: facts, relational queries, cycle-safe simple-path traversal, and the Chapter 7 hop-count arithmetic layer.
- =test_community.pl= :: PL-Unit regressions for the foundational relation/unification contract.
- =test_search.pl= :: PL-Unit regressions for backtracking, lists, paths, cycle handling, and explicit first-answer commitment.
- =test_arithmetic.pl= :: PL-Unit regressions for path-hop evaluation, complete path/count answer sets, hop-limit filtering, and the low-level arithmetic instantiation boundary.

* Run
From the repository root:

#+begin_src sh
bash books/prolog/code/run-tests
#+end_src

The runner prints the installed SWI-Prolog version before executing the tests. A missing =swipl= is a hard failure, not a skipped-success path. The Prolog runner also requires every named test unit before calling =run_tests/1= so a missing new suite cannot look green.

* Accepted foundation contracts
- Facts represent people, neighborhoods, mentoring, and project participation.
- =mentor(Mentor, Student)= is directed.
- =same_neighborhood/2= excludes self-pairs.
- =project_peer/3= reports the shared project and excludes self-pairs.
- Shared variables across goals constrain those goals to one consistent term.
- =unify_with_occurs_check/2= is exercised as the explicit sound-unification boundary.
- =connection_path/3= enumerates simple directed paths with branch-local visited state rather than silently committing to one proof.
- =first_connection_path/3= is the deliberately named first-answer policy boundary.

* Chapter 7 draft contract
Issue #84 adds a narrow arithmetic layer without changing the accepted path relation.

- =path_hops(+Path,-Hops)= counts edges in a finite proper non-empty path in the documented forward mode.
- =connection_with_hops/4= preserves the underlying path relation's multiplicity and annotates each proof with a count.
- =connection_within_hops(+Start,+Goal,+Limit,-Path,-Hops)= applies a ground numeric limit after proving and counting a path.
- The implementation deliberately uses ordinary =is/2= and arithmetic comparison so Chapter 7 can teach their evaluation/mode boundary before later CLP(FD) chapters.
- This milestone does not implement shortest-path search, optimization, cut, negation, DCGs, or CLP(FD).

The Chapter 7 code is a worker draft until actual SWI-Prolog tests and publication checks pass and the Editor-in-Chief accepts the bounded milestone.

* Failure labs
Work on temporary copies and introduce exactly one defect at a time. Record prediction, observed result, explanation, and fix; do not keep the broken change.

1. Capitalize the atom =harbor= in a fact and explain the newly introduced variable.
2. Reverse one =mentor/2= fact and identify the directionality regression.
3. Remove =dif(Person, Other)= from =project_peer/3= and predict the self-pairs.
4. Remove the visited-state check from path traversal and protect any cycle experiment with an explicit resource bound.
5. Move =Hops is TailHops + 1= before the recursive =path_hops/2= call and classify the insufficient-instantiation failure.
6. Replace the hop-limit comparison with a unification goal and explain why term matching does not implement numeric ordering.

* Planned evolution
- cut and negation are taught only after the relation/control contracts are explicit;
- modules split data, query logic, and interfaces once the module chapter establishes the semantics;
- DCGs begin Project 2 as a real parser rather than changing Project 1 into a syntax exercise;
- constraints/CLP(FD) later introduce genuinely relational integer problems in Project 3;
- persistence/integration later moves fact storage behind an explicit boundary;
- indexing/performance revisits stable query shapes at larger synthetic scale;
- explanation/meta-programming adds proof/explanation output without silently replacing the base relations.

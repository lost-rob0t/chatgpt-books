Foundation slice A researched production-system structure, naive condition matching, variables/bindings, joins, and provenance using Forgy's OPS5/RETE material, current official CLIPS documentation, and authoritative Linux/systemd sources for the technical fixture.

Foundation slice B researched and froze the next executable semantic boundary: mutable working-memory identity/occurrences, stable productions/activations, naive complete-rematch forward chaining, deterministic agenda policy, and explicit refraction. It remains intentionally upstream of incremental alpha/beta/RETE, truth maintenance, uncertainty, persistence, and benchmarks.

Foundation slice C researched the optimization boundary without changing the accepted rule language: current CLIPS 6.4.2 documentation corroborates the broad pattern-network -> partial-instantiation -> cross-pattern-binding -> activation model, while Forgy 1982 anchors the RETE lineage. Course-local node/cache semantics are recorded separately and are verified by executable equivalence against the complete-rematch oracle.

Foundation slice D researched the support-semantics boundary: Doyle 1979 anchors truth-maintenance lineage around recorded reasons/dependencies for beliefs, while current CLIPS 6.4.2 logical-CE documentation provides a maintained comparison for multiple support groups and retraction after final support loss. The accepted course implementation remains deliberately smaller and course-local: exact occurrence-stamped reasons, explicit base support, recursive grounding, and cascading retraction. It does not claim Doyle/CLIPS implementation equivalence.

Foundation slice E is MERGED through PR #102 as =d8131c4d1485d02eba228d6be13be4e15654d8d1=. Doyle 1979 and de Kleer 1986 ground the assumption/revision and ATMS lineage, while current systemd Unit D-Bus documentation grounds the technical ActiveState fixture. The accepted course layer keeps explicit assumption occurrence stamps, provenance-bearing contradiction pattern pairs, grounded counterevidence, temporal consistency keys, and an explicit halt-versus-report execution policy. It does not claim ATMS environments/nogoods, automatic belief preference, uncertainty semantics, or diagnosis.

Foundation slice F is ACTIVE in issue #115: Clancey 1983 and Aikins 1980 ground the historical explanation/explicit-knowledge boundary; Doyle 1979 supplies the recorded-reasons lineage already implemented by milestone D; current W3C PROV-DM supplies a domain-neutral provenance comparison vocabulary. The course layer derives deterministic read-only support graphs from exact current occurrences and explicitly avoids claiming PROV conformance, why-not completeness, uncertainty semantics, or natural-language explanation quality.

* Phases 4--6 -- progressive chapters/projects
Implement projects in the order listed in PROJECTS.org; later projects depend on foundations from earlier ones.

Project 1 milestone A is the merged semantic baseline: literal matcher -> variables/bindings -> deterministic multi-condition joins with supporting fact identities.

Project 1 milestone B is also merged: working-memory assertion/retraction and occurrence identity -> stable productions/complete activations -> conflict set/agenda -> deterministic conflict resolution -> bounded forward chaining -> occurrence-aware refraction. The implementation deliberately rematches completely after every firing so it remains a transparent correctness oracle.

Project 1 milestone C is merged through PR #80: incremental positive-pattern matching -> alpha memories -> beta memories -> join/token/production nodes -> RETE-like assertion/retraction propagation. The accepted implementation preserves milestone-B activation/refraction/agenda semantics through executable equivalence regressions and keeps cache-reference soundness distinct from cache completeness. It deliberately excludes negative/existential conditions, truth maintenance, uncertainty, persistence, TREAT implementation, and benchmark claims.

Project 1 milestone D is merged through PR #90 as =c340e5843981e33fe240d19797d9ef1354ed247d=. It adds exact support and conclusion occurrence identity, explicit base support, multiple independent reasons for one materialized conclusion, mixed base+derived support, recursive grounding that rejects unsupported cycles, cascading retraction through dependency edges, and explanation-facing support/dependency queries while preserving matcher/working-memory ownership boundaries.

Project 1 milestone E is merged through PR #102 as =d8131c4d1485d02eba228d6be13be4e15654d8d1=. Chapter 18 layers explicit assumption identity and declarative contradiction constraints over milestone D, preserves both grounded sides as counterevidence, carries context variables such as observation epoch through the consistency key, and adds a pre-next-firing =:halt= gate plus =:report-only= inspection mode. Resolution/preference, uncertainty, ATMS labels/environments/nogoods, and automatic diagnosis remain out of scope.

Project 1 milestone F is ACTIVE in issue #115. Chapter 20 derives explanation/provenance as a read-only graph over exact support and contradiction identity: current fact occurrences, base/assumption source nodes, current grounded justifications with production provenance, and contradiction roots with two counterevidence branches. Historical reasons and reports must fail closed when their exact occurrences are stale. Why-not/partial-match explanation and certainty/fuzzy semantics remain separate dependencies.

After editorial acceptance of milestone F, the highest-value project dependency is the substantial sourced Linux/server/distributed-service troubleshooting knowledge base in Project 2. Chapter 19 certainty/fuzzy material remains a separate research/implementation slice and must not be faked by arbitrary confidence numbers. TREAT and other matcher alternatives remain comparative architecture until separately researched, implemented, and verified.

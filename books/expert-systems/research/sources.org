** Doyle 1979 -- A Truth Maintenance System
Authority: original TMS author / MIT AI Laboratory primary report plus published-article metadata.
Primary artifact: https://dspace.mit.edu/entities/publication/5377b306-4ecc-4687-b1f5-78cbb4a0543a

** systemd.unit v261.3 -- requirement and ordering dependencies
Authority: upstream systemd repository, pinned stable release source.
URL: https://github.com/systemd/systemd/blob/v261.3/man/systemd.unit.xml
Release: v261.3, published 2026-09-10; retrieved 2026-09-16.
Inspected material: =Wants==, =Requires==, =Before==/=After== and surrounding dependency semantics. The source documents =Wants== as a weak requirement whose failed/cannot-add target does not invalidate the transaction as a whole; =Requires== as stronger and, with =After== on a required unit that fails activation, preventing the configuring unit from starting; and requirement dependencies as not determining ordering, which =Before==/=After== configure independently. The same source explicitly calls ordering dependencies independent/orthogonal to requirement dependencies.
Used by: Project 2 milestone A source-backed dependency rules and manuscript. The course relation names, activation-attempt key, configuration-generation key, stable IDs, and diagnostic-hypothesis/boundary vocabulary are local modeling choices, not claimed systemd data structures.

** Project 2 -- Technical Troubleshooting Knowledge Base
:PROPERTIES:
:ID:       74177fb5-740c-50cb-a8c4-345e1fea11bb
:END:
Purpose: Build a substantial Linux/server/distributed-service diagnosis KB with provenance, contradictions, temporal observations, and regression scenarios.

Milestone A, issue #120 / PR #123, is editorially APPROVED and merged as =44a1855d7585009fc371e77ed3f8e339d6fd79c4=. It replaces the early synthetic =depends-on= teaching abstraction with the first source-backed systemd dependency slice: requirement kind remains separate from ordering, activation attempt and configuration generation are explicit join keys, observations and rule-source provenance remain distinct, and current explanation graphs expose both. The bounded rules model documented v261.3 =Requires= + =After= + failed-required-unit behavior plus the =Wants= failure boundary; they do not claim a complete systemd model or real-host collection.

Milestone B is tracked by issue #131 / PR #132 and extends the accepted milestone-A model across exactly one machine-facing evidence boundary by accepting captured =systemctl show= property text rather than pre-normalized observation facts. The parser splits each non-empty line on the first equals sign, rejects malformed/duplicate/incomplete input before fact creation, optionally validates =Id== against the expected unit, and preserves raw property/capture provenance. The normalizer keeps each unit's real =InvocationID= separate from the caller-supplied cross-unit activation context and configuration generation used by the existing rule. It preserves =Result=, =ExecMainCode=, and =ExecMainStatus= as distinct evidence and never treats a nonzero main-process status as service failure; the bounded adapter emits =:failed= only for exact =ActiveState=failed=. The Editor-in-Chief has accepted this milestone-B content after direct manuscript/code/research review. It still does not execute =systemctl=, query D-Bus, parse journals, reconstruct activation transactions automatically, or claim production collection/diagnosis performance. Since milestone A is now canonical =main=, PR #132 must be normally reconciled/retargeted to =main= and pass fresh exact-head focused/generic/Nix gates before merge.

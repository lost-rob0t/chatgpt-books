** Failure-semantics pass 02 -- links, trapping exits, monitors, unlink, kill
Status: DOCUMENTED + EXECUTION VERIFIED for the merged checkpoint-B revision.

Primary-source scope: current OTP 29.0.6 Processes reference plus the OTP 29.0.6 =erlang= BIF reference. See [[file:sources.org][sources.org]] and [[file:search-log.org][search-log.org]].

This pass supports Chapters 7--9 and Project 1 checkpoint B. The contract taught by the book is intentionally narrower than folklore:
- links are bidirectional failure relationships and abnormal linked exits propagate unless the receiver traps exits;
- a non-trapping process normally ignores a linked exit whose reason is =normal=;
- =process_flag(trap_exit, true)= converts eligible exit signals into ordinary ={'EXIT', From, Reason}= messages; it does not create a restart policy;
- process monitors are unidirectional observations with independent references and correlated ={'DOWN', Ref, process, Pid, Reason}= messages;
- after =unlink(Pid)= returns, the former link has no future effect on the caller unless re-established, although an =EXIT= message may already be queued when exits are trapped;
- =demonitor(Ref, [flush])= combines monitor removal with removal of one already-queued matching =DOWN= notification when present;
- OTP 29 introduced =erlang:exit_signal/2= as the direct exit-signal API. An explicit =kill= signal is untrappable and the target terminates with reason =killed=.

Execution evidence for the final reviewed checkpoint-B head is recorded in =STATUS.org= and the merged PR #40 discussion. No performance benchmark is inferred from these semantics.

** OTP pass 03 -- behaviours, =gen_server= calls, and supervisor policy
Status: DOCUMENTED + EXECUTION VERIFIED for merged Project 2 checkpoint A; bounded Chapters 10--12 content is editorially APPROVED and merged through PR #54.

Primary-source scope: official Erlang/OTP =OTP-29.0.6= tagged source documentation for OTP Design Principles, =gen_server=, and =supervisor=, plus official 29.0.6 release metadata. See [[file:sources.org][sources.org]] and [[file:search-log.org][search-log.org]].

This pass supports Chapters 10--12 and Project 2 checkpoint A. It records these boundaries:
- OTP behaviours split recurring generic process machinery from application-specific callbacks; =gen_server= does not replace the process model or make callbacks concurrent;
- =gen_server:call/3= exits the caller on timeout, while timeout does not cancel callback work already executing;
- starting with OTP 24, synchronous =gen_server:call= uses process aliases so an abandoned late reply is not delivered to the caller mailbox;
- =gen_server= participates in the standard =sys= system-message/debugging protocol;
- a supervisor owns child lifecycle through child specifications and restart policy; =one_for_one=, =one_for_all=, and =rest_for_one= express different dependency assumptions;
- if more than =intensity= restarts occur within =period= seconds, the supervisor terminates its children and then itself with reason =shutdown=;
- a =permanent= child is always restarted while the supervisor remains able to restart it, but replacement process state comes from fresh initialization/recovery code rather than from the supervisor;
- OTP 29.0 introduced =supervisor:stop/1,3= style synchronous supervisor stop APIs; the Project 2 cleanup code is therefore explicitly version-pinned rather than advertised as historical-OTP portable.

Generic =books-ci= run =35122123275= also succeeded through structural validation, Pandoc Org-reader validation, deterministic assets/fixture, publication/citation regressions, ERT, real Org-roam DB synchronization, and artifact upload. The six Project 2 regressions cover behavior/state, modern call-timeout mailbox isolation, =sys= state introspection, supervised crash/restart, and restart-budget escalation. ** Application pass 04 -- application behaviour, =.app= metadata, and component lifecycle
Status: DOCUMENTED + EXECUTION VERIFIED; Chapter 13 / Project 2 checkpoint B was editorially APPROVED and merged through PR #78.

Primary-source scope: official Erlang/OTP source at immutable tag =OTP-29.1=: =OTP_VERSION=, the Applications design-principles chapter, Kernel =app= application-resource reference, and Kernel =application= source documentation. See [[file:sources.org][sources.org]] and [[file:search-log.org][search-log.org]].

This pass supports Chapter 13 and Project 2 checkpoint B. It records these boundaries:
- an OTP application is a reusable component that can be started and stopped as a unit; it is not synonymous with a release or deployment artifact;
- the application controller coordinates application load/start/stop/unload operations;
- a started supervision-tree application gets an application master, which invokes the callback module named by =mod= and tracks application process ownership;
- =start/2= normally starts the top supervisor and returns its PID; =stop/1= is post-tree cleanup, not a replacement for supervisor shutdown;
- the =Application.app= resource in =ebin= contains one application-specification term; =modules=, =registered=, =applications=, and =mod= describe different parts of the component contract;
- loading an application stores its specification but does not load all object code;
- =application:start/1= requires declared prerequisite applications to be running, while =ensure_all_started/1,2,3= can traverse/start the dependency set;
- stopping the application stops the owned process tree but does not unload its specification; neither operation is persistence;
- Project 2 continues to keep worker state volatile so a full application restart must create a new tree with empty history.

The executable checkpoint adds =otp_worker_app=, =otp_worker_app.app.src=, application-controller lifecycle regressions, and an editable application-ownership diagram. The accepted PR head =7ac3c69e54d30d2a412e1ea7933e6ef440c713d5= passed focused =erlang-book= run =35141056340= on strict OTP 29.1 / BEAM 17.1 with foundations 14/14 and the combined worker/application suite 10/10; diagram validation, book build/check, EPUBCheck with zero findings, and Nix evaluation also succeeded. ** Release pass 05 -- =.rel= composition, boot scripts, and target-system boundary
Status: DOCUMENTED + EXECUTION VERIFIED; Chapter 14 was editorially APPROVED and merged through PR #94.

Primary-source scope: official Erlang/OTP source at immutable tag =OTP-29.1=: Releases design-principles chapter, SASL =rel= reference, SASL =systools= source documentation, and target-system system-principles chapter. See [[file:sources.org][sources.org]] and [[file:search-log.org][search-log.org]].

This pass supports Chapter 14 and issue #91. It derives the next system boundary from the accepted application milestone:
- =.app= describes one application while =.rel= composes exact ERTS/application versions into a release;
- Kernel and STDLIB are required release members;
- =systools:make_script/2= validates application-version agreement, dependency closure, circular dependencies, and duplicate modules before deriving =.script= and binary =.boot= artifacts;
- =local= uses actual discovered application paths and is suitable for local boot testing; default output uses release-relative paths such as =$ROOT/lib/App-Vsn/ebin=;
- =systools:make_tar/2= packages validated application/release artifacts into target-system layout;
- SASL is needed for upgrade-capable releases, while upgrade/relup behavior is deliberately deferred.

The accepted release lab compiles =otp_worker_app=, derives a release from the runtime's real ERTS/Kernel/STDLIB versions, boots a fresh VM from a generated local boot file, rejects deliberate version/dependency defects, and inspects the release package. ** Project 3 pass 06 -- bounded work, dynamic children, and retry ownership
Status: DOCUMENTED + EXECUTION VERIFIED; Chapter 15 / Project 3 checkpoint A was editorially APPROVED and merged through PR #108.

Primary-source scope: official Erlang/OTP source at immutable tag =OTP-29.1= for =supervisor= and =queue= plus the immutable processes reference manual. Detailed notes and exact execution evidence live in [[file:job-processor-pass-06.org][job-processor-pass-06.org]].

This pass supports Chapter 15 and issue #106 / PR #108. It establishes these boundaries:
- application backlog is explicit state, not an accidental use of the =gen_server= mailbox;
- =max_active + max_queued= defines a course-local admission policy, not an OTP guarantee;
- dynamic =temporary= supervisor children own one worker process lifetime, while =job_processor= owns logical job identity and retry budget;
- monitors correlate a worker termination with one active attempt but do not decide whether replay is safe;
- retries are re-enqueued at the FIFO rear as an explicit fairness policy;
- restarting =job_processor= restores the process role but does not reconstruct its volatile accepted-work ledger.

** Project 4 pass 07 -- distributed identity, connection loss, and remote-process failure
Status: DOCUMENTED; execution UNTESTED until the focused workflow runs the new multi-node lab.

Primary-source scope: official Erlang/OTP source at immutable tag =OTP-29.1= for Distributed Erlang, =net_kernel=, =erlang:monitor/2=, STDLIB =peer=, and Secure Coding Guidelines. Detailed notes live in [[file:distribution-pass-07.org][distribution-pass-07.org]].

This pass supports Chapter 16 and issue #127. It deliberately separates:
- node identity from process identity and node-local registered names;
- remote process-monitor outcomes (=real exit=, =noproc=, =noconnection=) from connection-level =nodeup=/=nodedown= observations;
- one connection incarnation from a later connection to the same node through =connection_id=;
- the application transport (ordinary Erlang Distribution) from the test harness's =peer= standard-I/O control channel;
- a same-host local multi-node experiment from any claim about real WAN partitions, cross-host availability, TLS deployment, or production failover.

The critical claim under test is intentionally negative: =noconnection= establishes loss of the observer's distribution path, not proof that the remote service process or VM died. The same-host lab uses the independent peer control channel to verify service liveness while Erlang Distribution is deliberately disconnected, then reconnects, observes a new connection ID, installs a fresh process monitor, and issues a new request.

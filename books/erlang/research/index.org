** Failure-semantics pass 02 -- links, trapping exits, monitors, unlink, kill
Status: DOCUMENTED + EXECUTION VERIFIED for the merged checkpoint-B revision.

Primary-source scope: current OTP 29.0.6 Processes reference plus the OTP 29.0.6 =erlang= BIF reference. See [[file:sources.org][sources.org]] and [[file:search-log.org][search-log.org]].

This pass supports Chapters 7--9 and Project 1 checkpoint B. The contract taught by the book is intentionally narrower than folklore:
- links are bidirectional failure relationships and abnormal linked exits propagate unless the receiver traps exits;
- a non-trapping process normally ignores a linked exit whose reason is =normal=;
- =process_flag(trap_exit, true)= converts eligible exit signals into ordinary ={'EXIT', From, Reason}= messages; it does not create a restart policy;
- process monitors are unidirectional observations with independent references and correlated ={'DOWN', Ref, process, Pid, Reason}= messages;
- after =unlink(Pid)= returns, the former link has no future effect on the caller unless re-established, although an =EXIT= message may already be queued when exits are trapped;
- =demonitor(Ref, [flush])= combines monitor removal with removal of one already-queued matching =DOWN= notification when present;
- OTP 29 introduced =erlang:exit_signal/2= as the direct exit-signal API. An explicit =kill= signal is untrappable and the target terminates with reason =killed=.

Execution evidence for the final reviewed checkpoint-B head is recorded in =STATUS.org= and the merged PR #40 discussion. No performance benchmark is inferred from these semantics.

** OTP pass 03 -- behaviours, =gen_server= calls, and supervisor policy
Status: DOCUMENTED + EXECUTION VERIFIED for Project 2 checkpoint A implementation; editorial review remains pending.

Primary-source scope: official Erlang/OTP =OTP-29.0.6= tagged source documentation for OTP Design Principles, =gen_server=, and =supervisor=, plus official 29.0.6 release metadata. See [[file:sources.org][sources.org]] and [[file:search-log.org][search-log.org]].

This pass supports Chapters 10--12 and Project 2 checkpoint A. It records these boundaries:
- OTP behaviours split recurring generic process machinery from application-specific callbacks; =gen_server= does not replace the process model or make callbacks concurrent;
- =gen_server:call/3= exits the caller on timeout, while timeout does not cancel callback work already executing;
- starting with OTP 24, synchronous =gen_server:call= uses process aliases so an abandoned late reply is not delivered to the caller mailbox;
- =gen_server= participates in the standard =sys= system-message/debugging protocol;
- a supervisor owns child lifecycle through child specifications and restart policy; =one_for_one=, =one_for_all=, and =rest_for_one= express different dependency assumptions;
- if more than =intensity= restarts occur within =period= seconds, the supervisor terminates its children and then itself with reason =shutdown=;
- a =permanent= child is always restarted while the supervisor remains able to restart it, but replacement process state comes from fresh initialization/recovery code rather than from the supervisor;
- OTP 29.0 introduced =supervisor:stop/1,3= style synchronous supervisor stop APIs; the Project 2 cleanup code is therefore explicitly version-pinned rather than advertised as historical-OTP portable.

Both the existing Project 1 foundations step and the new Project 2 OTP-worker EUnit step succeeded, as did production book build/check and the separate Nix flake evaluation. The six Project 2 regressions cover behavior/state, modern call-timeout mailbox isolation, =sys= state introspection, supervised replacement with fresh process-local state, and restart-budget escalation. This is execution evidence for those bounded mechanisms, not a performance or availability benchmark.

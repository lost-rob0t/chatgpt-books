** 2026-09-16 -- foundational pass 01: current release and language/process semantics
- Questions :: What is the current Erlang/OTP major/patch level? What do the current reference manuals actually guarantee about variable binding, match failure, process creation/termination, signal ordering, mailbox insertion, monitors, selective receive, and message copying? Which beginner statements became version-sensitive after priority messages?
- Queries :: Official erlang.org OTP 29 release/patch pages; Erlang System Documentation pages for Data Types, Pattern Matching, Processes, Errors and Error Handling, Efficiency Guide Processes, and stdlib gen_server.
- Sources inspected :: See [[file:sources.org][sources.org]], foundational pass 01.
- Result :: OTP 29.0 released 2026-05-13; OTP 29.0.6 published 2026-09-01. The process reference guarantees ordering for multiple signals from the same sender entity to the same destination, not a global order across senders. Messages are normally appended to the queue in received-signal order, but OTP 28+ priority-message reception can change queue insertion order for participating processes. Monitors are unidirectional and produce correlated DOWN messages. Local receive timeouts do not retract messages already sent. The efficiency guide documents message copying with exceptions for reference-counted binaries/literals and warns that selective receive may scan the queue.
- Claim classification :: DOCUMENTED from primary sources. Project 1 execution remains UNTESTED until run on an Erlang/OTP runtime.
- Remaining uncertainty :: Exact runtime behavior/performance under mailbox overload is intentionally not inferred from documentation; later project phases require measured failure demonstrations. Links, supervisor restart intensity, application/release semantics, distribution/TLS, persistence, tracing, and production debugging remain future research passes.

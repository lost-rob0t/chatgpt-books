** Chapter 15 -- Bounded Work And Dynamic Workers
Goal: derive bounded admission, an explicit FIFO, dynamic temporary workers, monitor-correlated attempts, and logical retry ownership for Project 3. Make overload and volatile-ledger loss executable rather than hiding work in an unbounded mailbox.
Dependencies: applications/releases plus the earlier process, monitor, gen_server, and supervisor chapters.
Examples: one active + one queued capacity rejection; FIFO dispatch; deliberate worker crash/retry; retry exhaustion; queue-process restart while a sibling worker remains alive.
Exercises: ★ admission/ownership explanation, ★★ cancellation/deadline modifications, ★★★ alternate supervision/recovery designs.
Visuals: admission/FIFO -> dynamic supervisor -> temporary worker -> completion/DOWN/retry trace, with the queue-restart persistence boundary shown explicitly.
Expected code: executable Project 3 checkpoint A modules and EUnit tests on strict OTP 29.1.
Research: immutable OTP 29.1 =supervisor=, =queue=, and process-reference sources; distinguish documented runtime mechanics from course-local retry/backpressure policy.
** Chapter 16 -- Distribution
Goal: begin Project 4 by extending the already-taught process/message model across a real node boundary while keeping node identity, process identity, registered names, process-monitor evidence, and distribution-connection evidence distinct. Teach explicitly that =noconnection= is evidence about the observer's path, not proof that the remote process or VM died.
Dependencies: Chapters 1--15, especially message protocols, monitors, OTP application/release boundaries, and Project 3's explicit ownership/failure semantics.
Examples: same-host peer-node request/reply; deliberate remote service crash while the peer stays connected; missing remote registration yielding =noproc=; deliberate Distribution disconnect yielding process-monitor =noconnection= plus =nodedown=; independent =peer= standard-I/O control proving the service is still alive; reconnect with a new connection ID, a fresh process monitor, and a successful new request.
Exercises: ★ interpret =noproc=/=noconnection=/real-exit evidence, ★★ add timeout and connection-ID-aware client state, ★★★ specify the durable state needed before accepted work could be replayed safely and design a TLS-distribution deployment boundary without pretending the teaching cookie is production security.
Visuals: origin node ↔ Erlang Distribution ↔ peer node/service, with separate process-monitor, node-monitor, and test-only standard-I/O control paths; show disconnect and reconnect as distinct connection identities.
Expected code: executable Project 4 checkpoint-A service and real multi-node EUnit scenarios using OTP 29.1 =peer= and =net_kernel:monitor_nodes/2=.
Research: immutable OTP 29.1 Distributed Erlang, =net_kernel=, =erlang:monitor/2=, STDLIB =peer=, and Secure Coding Guidelines. Keep same-host TESTED observations separate from WAN/partition/failover claims, and distinguish =connect_all=false= from =dist_auto_connect=.

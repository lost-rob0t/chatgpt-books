** Project 1 -- Process-Based Messaging System
:PROPERTIES:
:ID:       13645c4b-038c-5970-99f3-e6852768fd95
:END:
Purpose: Build process protocols with links, monitors, timeouts, failures, and tests.
Learning outcomes: integrate multiple chapter concepts; make architecture/test/provenance tradeoffs explicit.
Prerequisites: the chapters listed in OUTLINE.org before this project's integration point.
Relevant chapters: staged across the curriculum; final integration is dependency-gated in ROADMAP.org.
Architecture: split domain logic, interfaces, persistence/external boundaries, tests, and observability rather than one monolith.
Implementation language/tooling: selected to match the book subject; dependencies must be pinned/reproducible.
External dependencies: public/synthetic data and primary documentation only unless a later issue records an approved dependency.
Tests: unit + scenario/regression tests; add property/integration/performance tests when the architecture warrants them.
Failure scenarios: invalid input, boundary failure, contradictory/edge cases, and one operational/debugging failure.
Visuals: at least one architecture or execution-flow figure plus traces/plots when useful.
Research requirements: verify version-sensitive APIs and theoretical claims from primary sources before implementation.
Expected deliverable: runnable implementation, tests, design notes, diagrams, exercises, and an exportable project chapter.
** Project 2 -- OTP Worker Service
:PROPERTIES:
:ID:       80c110b1-bc1a-56d6-ae93-924c4b541baf
:END:
Purpose: Convert the Project 1 process lessons into a conventional OTP service and carry it through an explicit application boundary without hiding BEAM process/failure semantics.
Learning outcomes: derive behaviour callbacks from an ordinary server loop; distinguish =gen_server= request/state semantics from supervisor lifecycle policy; package the resulting supervision tree as a loadable/startable/stoppable OTP application; debug ownership at worker, supervisor, and application-controller layers; explain why none of those layers implies durable state recovery.
Prerequisites: Chapters 1--12 and the accepted Project 1 checkpoints.
Relevant chapters: Chapters 10--13. Checkpoint A covers behaviour + supervised worker; checkpoint B completes the application-lifecycle boundary.
Architecture: =otp_worker= owns domain transitions and volatile state; =gen_server= owns generic server mechanics; =otp_worker_sup= owns child lifecycle/restart policy; =otp_worker_app= and =otp_worker_app.app= expose the component lifecycle to OTP. Persistence, releases, distribution, and deployment remain outside this project checkpoint.
Implementation language/tooling: Erlang/OTP, with the focused workflow pinning the exact OTP version used for executable evidence.
External dependencies: official Erlang/OTP primary documentation/source plus repository publication tooling only.
Tests: EUnit regressions cover call/cast behavior, timeout mailbox isolation, =sys= inspection, supervised crash/restart, restart-intensity escalation, application resource metadata, application-controller startup/ownership, component stop, and fresh volatile state after a full application restart.
Failure scenarios: delayed calls, deliberate worker crashes, restart-budget exhaustion, application stop/restart, and application-specification debugging exercises.
Visuals: editable worker/supervisor lifecycle diagram plus an application-controller/application-master ownership diagram.
Research requirements: use immutable official Erlang/OTP tags for version-sensitive =gen_server=, supervisor, application, and =.app= contracts; preserve older exact-version evidence rather than silently rewriting historical test baselines.
Expected deliverable: runnable OTP worker application, executable lifecycle tests, Chapters 10--13, failure labs, editable diagrams, sourced claims, and a bounded handoff to release packaging.
** Project 3 -- Supervised Job Processor
:PROPERTIES:
:ID:       6d9afccc-5159-5527-9caf-447701fc748e
:END:
Purpose: Turn the earlier supervision lessons into a bounded work system whose overload, worker-crash, retry, and state-loss behavior is explicit before distribution or persistence is introduced.
Learning outcomes: distinguish runtime mailbox traffic from an application work queue; define the point at which =submit/1= accepts ownership; use dynamic =temporary= supervisor children for one-shot worker lifetime; correlate worker attempts with monitors; keep logical job identity/retry budget outside generic supervisor restart policy; explain why a restarted queue process does not reconstruct its volatile ledger.
Prerequisites: Chapters 1--14, including the merged OTP application and release boundaries.
Relevant chapters: Chapter 15 introduces checkpoint A; later distribution, persistence/recovery, tracing/testing, and measured-backpressure chapters extend the same project rather than replacing it.
Architecture: =job_processor_sup= has =job_worker_sup= and =job_processor= as =one_for_one= siblings. =job_processor= owns bounded admission, explicit FIFO pending state, client/job identity, active monitor ledger, and attempt budget. =job_worker_sup= owns dynamic temporary worker process lifetime. =job_worker= executes one synthetic test payload per attempt. Checkpoint A is intentionally volatile: no durable queue/replay contract exists yet.
Implementation language/tooling: Erlang/OTP 29.1 in the focused workflow; STDLIB =queue=; EUnit scenario tests; editable Graphviz execution/failure diagram.
External dependencies: official immutable Erlang/OTP 29.1 source/documentation plus repository publication tooling only.
Tests: bounded one-active/one-queued overload rejection; FIFO pending order; first-attempt crash followed by second-attempt success; retry-budget exhaustion; automatic removal of temporary child specs after completion; queue-process kill/restart proving that the replacement process has an empty ledger and does not recover the old in-flight result.
Failure scenarios: explicit overload, deliberate worker crash, repeated worker crash, and queue-process loss while a sibling temporary worker is still alive.
Visuals: =job-processor-flow.dot/svg= shows admission, FIFO, dynamic supervisor/worker, completion/DOWN retry paths, and the separate volatile-ledger loss after queue restart.
Research requirements: immutable OTP 29.1 =supervisor=, =queue=, and processes reference manual. Treat capacity, retry placement, and attempt budget as course-local policy, not OTP guarantees. Preserve a hard boundary between observed local behavior and later durability/distribution claims.
Expected deliverable: Chapter 15, runnable checkpoint-A modules/tests, research pass 06, editable diagram, a production-EPUB regression that keeps accepted Chapters 13--15 in the canonical include path, and a dependency-ready handoff to distribution/persistence work.

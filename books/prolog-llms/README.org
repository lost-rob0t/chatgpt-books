* Purpose
A standalone, project-driven technical book that teaches enough Prolog to build trustworthy integrations with language models, then uses that foundation to study and implement neuro-symbolic systems. The book is not a prompt-engineering catalog and not an excuse to hide reasoning behind an API call. Readers should understand the symbolic program, the model boundary, the failure modes, and the evidence supporting every claimed capability.

The intended finished scope is roughly 300--700 rendered EPUB pages. The current manuscript is an in-progress foundation, not a finished book.

* Audience
Programmers who want to combine Prolog with LLMs, including readers who have never used Prolog before. Prior experience with Python or another general-purpose language is useful but not required for the logic-programming sections.

* Standalone promise
The book teaches a compact but real Prolog foundation: facts, rules, queries, unification, recursion, lists, backtracking, modules, DCGs, constraints, meta-programming, testing, and debugging appear before the reader is asked to trust a Prolog/LLM integration. The sibling [[file:../prolog/README.org][Prolog for Beginners]] remains the deeper pure-Prolog course; this volume does not hollow it out or require it as a prerequisite.

* Boundaries with sibling books
- [[file:../prolog/README.org][Prolog for Beginners]] owns the broadest pure-Prolog beginner-to-capable treatment.
- [[file:../symbolic-ai-prolog/README.org][Symbolic AI in Prolog]] owns deeper symbolic-AI algorithms, explicit meta-interpreters, planning, abduction, and proof machinery as symbolic systems in their own right.
- [[file:../expert-systems/README.org][Expert Systems]] owns production rule engines, RETE/TREAT-style matching, truth maintenance, and knowledge-engineering workbenches.
- This book owns the integration problem: typed model boundaries, structured generation, tool use, retrieval/knowledge handoff, symbolic verification, repair loops, evaluation, provenance, and concrete Prolog-RLM-style architectures.

* Teaching method
Every major idea enters through a system that currently fails in an understandable way. We begin with deterministic Prolog programs and tests, introduce an LLM only when the symbolic program has a crisp boundary for it, then deliberately inject malformed model output, hallucinated predicates, schema mismatches, timeouts, contradictory evidence, nontermination, and misleading explanations. Readers should learn to separate DOCUMENTED behavior, TESTED behavior, EXPERIMENTAL hypotheses, and model-dependent observations.

* Current implementation slice
Project 1 now carries the standalone foundation through relations/unification, recursion and cycle-safe dependency traversal, explicit multi-answer backtracking versus a named first-answer =once/1= boundary, module/API composition, PL-Unit contracts, provenance-bearing explanations, and a small closed DCG task-command language. The accepted parser milestone separates full-input parsing from prefix/remainder parsing, constructs only four typed AST shapes, and routes those data terms through an explicit allowlisted dispatcher rather than arbitrary =call/1=.

The current milestone adds a separate model-free CLP(FD) scheduling worksheet. =schedule_constraints/2= posts finite start domains, precedence, one release-time requirement, a derived two-job non-overlap relation for a shared verifier, and makespan without hiding labeling. =first_minimum_schedule/2= makes the optimization/search and first-answer commitment explicit; =deadline_flag/3= reifies a deadline relation into typed =0/1= data. This does not mutate the accepted task/dependency fixture and does not grant external data authority to choose predicates or search options. Bounded meta-programming is the next standalone-Prolog dependency before provider/model integration.

* Research and evidence
Current behavior of SWI-Prolog, model APIs, structured-output facilities, tool protocols, and any named neuro-symbolic system must be verified against primary sources/current implementations before version-sensitive prose is promoted. Record queries and retrieval dates in =research/search-log.org= and verified source metadata in =research/sources.org= / =references.bib=. Never fabricate model output, benchmark numbers, or execution results.

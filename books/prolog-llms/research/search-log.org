Sources inspected:
- current official SWI-Prolog =library(clpfd)= manual at =https://www.swi-prolog.org/man/clpfd.html=;
- Markus Triska, =The Finite Domain Constraint Solver of SWI-Prolog=, FLOPS 2012, primary PDF at =https://www.metalevel.at/swiclpfd.pdf=; bibliographic metadata cross-checked against the citation recommended by the current SWI manual.

Result:
- DOCUMENTED: =in/2= and =ins/2= constrain domains while =labeling/2= is an explicit enumeration/search operation; the manual recommends keeping the core constraint relation separate from labeling policy.
- DOCUMENTED, SWI-SPECIFIC: =ffc= is a labeling variable-selection strategy and =min(Expr)= orders generated solutions by increasing objective value. The manual notes =once/1= as an explicit way to keep only the first optimal solution while alternatives may still be useful.
- DOCUMENTED: reification reflects supported constraint truth values into finite-domain Boolean values 0/1, including equivalence through =#<==>/2=.
- DOCUMENTED from the primary 2012 paper: the presented solver treats scheduling/planning/allocation as canonical CLP(FD) use cases and discusses terminating propagation, large integer domains, and a DSL for reification.
- UPSTREAM-REPORTED: historical solver performance observations in the paper; this book did not reproduce them.

* 2026-09-17 -- architecture case studies: what crosses the neural/symbolic boundary?
Questions:

Search/source paths inspected 2026-09-17:
- Gao et al., =PAL: Program-aided Language Models=, arXiv:2211.10435;
- Chen et al., =Program of Thoughts Prompting=, arXiv:2211.12588;
- Lyu et al., =Faithful Chain-of-Thought Reasoning=, arXiv:2301.13379;
- Ye et al., =SatLM: Satisfiability-Aided Language Models Using Declarative Prompting=, official NeurIPS 2023 proceedings / DOI =10.52202/075280-1974=;
- Pan et al., =Logic-LM=, arXiv:2305.12295;
- Olausson et al., =LINC=, arXiv:2310.15164;
- Liu et al., =LLM+P=, arXiv:2304.11477;
- Zhang, Kraska, Khattab, =Recursive Language Models=, arXiv:2512.24601;
- read-only =lost-rob0t/prolog-rlm= main, rechecked at exact revision =51d2530f0e18c84cff860b7c0bf3afcc3c488057=;
- repository-local Project 1 capability dispatcher and CLP(FD) schedule worksheet as the already-accepted execution mechanisms available to a model-free teaching workbench.

Result:
- DOCUMENTED: PAL and Program of Thoughts make a generated program the handoff artifact and delegate execution/computation to an external runtime. Correct execution of the program does not independently prove that the program faithfully represents the source problem.
- DOCUMENTED: Faithful CoT explicitly separates translation into a symbolic reasoning chain from deterministic solving of that chain. Its answer can therefore be a faithful consequence of an emitted chain while the chain itself remains a model-produced translation.
- DOCUMENTED: SatLM moves the handoff from imperative program to declarative task specification and explicitly scopes solver correctness to the parsed specification.
- DOCUMENTED: Logic-LM and LINC formalize natural-language logical problems for external symbolic solvers/theorem provers; Logic-LM additionally feeds solver error messages into self-refinement. Semantic-parser errors remain separate from solver correctness.
- DOCUMENTED: LLM+P formalizes natural-language planning problems as PDDL, delegates search to a classical planner, and translates the returned plan back to natural language. Planning-engine depth belongs to =books/symbolic-ai-prolog= here.
- DOCUMENTED: RLM externalizes the prompt as an environment the model may inspect/decompose and introduces recursive sub-model calls; recursive inference therefore needs explicit host accounting and stopping rules in any serious implementation.
- DOCUMENTED from read-only source recheck: current Prolog-RLM main remains =51d2530f0e18c84cff860b7c0bf3afcc3c488057=. Issue #129 still treats its runtime as source evidence, not local TESTED behavior.

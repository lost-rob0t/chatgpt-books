** NumPy 2.5 documentation
Authority: official NumPy documentation and official NumPy release-news page.
Release evidence: NumPy 2.5.0 was released 2026-06-21. The official news page lists later 2.5.x bugfix releases, including NumPy 2.5.3 on 2026-09-06. Project 1 deliberately pins 2.5.0 as the TESTED numerical oracle; it does not claim 2.5.0 is the newest 2.5-series patch.
URLs:
- https://numpy.org/news/
- https://numpy.org/doc/2.5/reference/generated/numpy.dot.html
- https://numpy.org/doc/2.5/reference/generated/numpy.linalg.vector_norm.html
- https://numpy.org/doc/2.5/reference/generated/numpy.testing.assert_allclose.html
- https://numpy.org/doc/2.5/reference/generated/numpy.matmul.html
- https://numpy.org/doc/2.5/reference/generated/numpy.ndarray.shape.html
- https://numpy.org/doc/2.5/reference/generated/numpy.gradient.html
- https://numpy.org/doc/2.5/reference/generated/numpy.linalg.lstsq.html
Inspected material: 1-D =numpy.dot= semantics; dimension errors; vector-norm API; numerical comparison support; 2.5-series release chronology; =ndarray.shape= dimension tuples; conventional 2-D =matmul= behavior and the =(n,k),(k,m)->(n,m)= compatibility signature; 2-D/1-D multiplication; mismatch errors; and the =@= operator relationship. For calculus, =numpy.gradient= was inspected for its sampled N-dimensional contract, second-order central differences at interior points, one-sided boundary behavior, explicit spacing support, and documented evenly spaced central-difference error term. For Project 2, =numpy.linalg.lstsq= was inspected for its least-squares objective, return contract, and minimum-norm behavior when multiple minimizers exist.
Used by: Project 1's independent vector/matrix oracle, the calculus lab's bounded sampled-gradient oracle, and Project 2's independent ordinary finite least-squares oracle. NumPy is deliberately not used to implement the teaching algorithms themselves.

** Python 3.14.7 floating-point tutorial
Authority: official Python documentation.
URL: https://docs.python.org/3.14/tutorial/floatingpoint.html
Version at retrieval: Python 3.14.7 documentation.
Inspected material: binary representation error, per-operation rounding, =math.fsum= as a more accurate summation tool, and the statement that almost all current platforms map Python =float= to IEEE 754 binary64 values.
Used by: the Project 1 matrix numerical-failure lab separating exact real-number associativity from finite-precision execution behavior, the calculus finite-difference step-size/cancellation failure discussion, Project 2's fail-closed finite-arithmetic boundary, and Project 3's explicit distinction between an exact recurrence over the reals and bounded floating-point execution evidence.

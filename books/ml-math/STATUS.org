* Active slice -- Project 2 checkpoint A: fit the line you can audit
WORKER DRAFT / RESEARCH DOCUMENTED / TESTED / OBJECTIVE GATES GREEN ON PRE-HANDOFF HEAD / READY FOR EDITOR-IN-CHIEF REVIEW AFTER FINAL STATUS-HEAD GATE.

The active slice starts from the accepted affine-MSE gradient rather than reimplementing calculus. It derives the explicit update

=(w,b) <- (w,b) - eta * grad L=

for full-batch gradient descent, records every loss/gradient/parameter state, and makes step-budget exhaustion visible through =converged=False=. The same fixed six-row training fixture is fitted independently with a centered one-feature least-squares formula and checked against pinned NumPy 2.5.0 =numpy.linalg.lstsq= as an external oracle. Three additional rows are held out from parameter fitting and used only for post-fit MSE calculation; that boundary is not promoted into a statistical generalization claim.

The slice also introduces explicit failure material: identical feature values reject the unique-slope closed-form contract, a deliberately large finite learning rate produces a bounded fixture-specific worsening trace, invalid/non-finite values fail closed, and large finite scales that overflow intermediate arithmetic raise instead of returning =nan=/infinity. A deterministic SVG combines fit/residual geometry with the optimizer's recorded loss trace.

Local development exercised the implementation before repository CI, but the available local NumPy was 2.3.5 rather than the repository's pinned 2.5.0. Those observations remain development evidence only. The repository gate on pre-handoff head =9e65a20a97b9f95c3e9a1bc08f1fddaf63983f07= subsequently verified the slice under CPython 3.14.7 with pinned NumPy 2.5.0; because this STATUS update changes the branch head, one final exact-head gate is still required before worker handoff.

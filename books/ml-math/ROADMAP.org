* Phase 0 -- scope
DONE bootstrap purpose, audience, topics, and project boundaries.
* Phase 1 -- foundational research
IN-PROGRESS verify theory, current toolchain behavior, canonical implementations, and source bibliography.

Foundation pass A covers the arithmetic-to-vector dependency chain, author-maintained linear-algebra sequencing, the current NumPy numerical oracle, and Python floating-point primitives used by Project 1 checkpoint A.

Foundation pass B covers matrix shape/indexing, =Ax= as row dot products and column linear combinations, compatible =AB= multiplication, composition/identity/noncommutativity/associativity, two-dimensional linear-transformation geometry, and the finite-precision boundary between algebraic associativity and actual floating-point execution. The source record also captures the current NumPy 2.5 =matmul= and =ndarray.shape= behavior used by the oracle tests plus the official Python floating-point guidance used by the numerical failure lab.

Foundation pass C covers the calculus/derivatives dependency: secant-to-tangent derivative definition and scalar chain rule against MIT OpenCourseWare 18.01SC, partial derivatives/gradients/directional derivatives against MIT OpenCourseWare 18.02SC, and the sampled finite-difference oracle boundary against official NumPy 2.5 =gradient= documentation. The teaching lab keeps exact derivative claims separate from finite-difference TESTED evidence and carries forward the documented Python floating-point step/cancellation boundary.

Project 2 pass D covers least-squares/model-fitting context against Boyd and Vandenberghe's author-maintained applied-linear-algebra material, the descent-method update/stopping boundary against their unconstrained-optimization material, and the external least-squares oracle against official NumPy 2.5 =linalg.lstsq= documentation.

Project 3 pass E is active. It uses Boyd and Vandenberghe Chapter 9 for the documented gradient-descent/descent-method context and the existing official Python floating-point record for finite-arithmetic boundaries, while deriving the scalar fixed-step recurrence and its regimes directly in this book. Probability, information theory, multivariate/regularized regression, general Hessian/eigenvalue optimization theory, decompositions, and later-project research remain open.
* Phase 2 -- curriculum
IN-PROGRESS review sequence and cross-book dependencies while executable chapter/project slices are written. The current sequence preserves arithmetic/functions/coordinates before vector algebra, matrices/transformations before calculus-heavy projects, a bounded one-feature regression checkpoint immediately after the calculus foundation, then an explicit optimizer-behavior checkpoint before probability and later general optimization theory.

* Phases 4--6 -- progressive chapters/projects
IN-PROGRESS implement projects in the order listed in PROJECTS.org; later projects depend on foundations from earlier ones.

Project 1 checkpoint A is the accepted and merged vector semantic baseline: validated finite vectors, component-wise operations, dot product, Euclidean norm/distance, normalization, cosine similarity, projection, NumPy oracle tests, numerical failure cases, and a reproducible projection diagram.

This checkpoint does not claim later solving/decomposition/calculus/optimization work.

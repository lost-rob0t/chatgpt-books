** 2026-09-16 -- correlation, selective receive, timeout, ordering, and monitors
Question: Which process/message claims can Chapters 8--10 make from current official Erlang documentation, and which require executable evidence?
Sources inspected: Erlang System Documentation v29.0.6 process reference and the official process Efficiency Guide.
Result: sends are asynchronous signals; =receive= selects the first matching queued message; signal ordering is guaranteed from one sender to one destination rather than globally across independent senders; selective receive can scan queued messages; monitors are unidirectional and deliver a correlated =DOWN= message; a local receive timeout does not itself specify remote cancellation or target death. ** 2026-09-16 -- supervision strategy, restart intensity, and state recovery boundary

** 2026-09-17 -- default distribution security boundary
Question: Can the same-host cookie setup in the Project 4 lab be presented as a production deployment recipe?
Sources inspected: current Distributed Erlang documentation, OTP 29 Secure Coding Guidelines, and official Erlang Distribution over TLS documentation.
Result: no. The Project 4 fixed cookie/plain distribution setup is therefore labeled test-only; TLS, certificate trust, EPMD/network policy and cross-host deployment need their own reproducible slice.
Remaining uncertainty: no TLS configuration is claimed until a later checkpoint actually provisions certificates, exercises successful/failed trust paths, and runs the distributed application through that transport.

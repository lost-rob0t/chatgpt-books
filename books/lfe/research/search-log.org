** 2026-09-16 -- current Erlang term/pattern/process semantics
Question: Which BEAM semantics must the LFE book teach directly rather than treating LFE as isolated syntax?
Sources inspected: Erlang System Documentation =data_types.html= v29.0.5, =expressions.html= and =patterns.html= v29.0.6, and =ref_man_processes.html= v29.0.6.
Result: terms/lists/tuples/maps and single-assignment pattern semantics remain the foundation. Process communication is asynchronous signaling. Message ordering is not a universal cross-sender FIFO guarantee; current docs state same-sender-to-same-destination signal ordering, and OTP 28 priority-message reception can change queue ordering relative to signal arrival.
Remaining uncertainty: priority-message APIs themselves are outside the current project slice and require dedicated testing before use.

* Major Projects
** Project 1 -- LFE DSL
:PROPERTIES:
:ID:       55542619-da75-550e-a955-874f79c97643
:END:
Purpose: Design, macro-expand, test, and document a useful domain-specific language.
Learning outcomes: integrate multiple chapter concepts; make architecture/test/provenance tradeoffs explicit.
Prerequisites: staged from Chapters 1--7 and revisited in Chapter 16.
Relevant chapters: Chapters 1--3 define the semantic kernel as data/patterns/recursion; Chapters 4--5 make the function/data interface explicit; Chapters 6--7 add and audit the macro surface; Chapter 16 evaluates the resulting DSL as a language design.
Architecture: keep the semantic routing kernel explicit and independently testable; macros are a source layer, not a replacement runtime. Split domain logic, interfaces, tests, and later operational boundaries rather than one monolith.
Implementation language/tooling: LFE compiled to BEAM; dependencies and LFE release are pinned/reproducible in the executable book gate.
External dependencies: public/synthetic data and primary documentation only unless a later issue records an approved dependency.
Tests: unit/scenario regressions plus direct Erlang-to-LFE interoperability at the real BEAM module boundary; macro work adds exact exported-macro expansion equality via the documented top-level expander, a separate compiled macro consumer, deliberate non-hygienic capture evidence, and a compile-failure fixture for unsupported DSL syntax.
Failure scenarios: malformed event, malformed rule, no matching route, order-dependent shadowing, missing recursive base case, invalid macro syntax/expansion, and variable capture in deliberately unsafe teaching macros.
Visuals: event/rule execution-flow figure plus macro-expansion/runtime-boundary figure; later runtime figures as those stages land.
Research requirements: verify version-sensitive APIs and macro behavior from primary LFE/Erlang sources before implementation.
Expected deliverable: runnable implementation, tests, design/research notes, diagrams, exercises, and an exportable project chapter.
Current staged implementation: *Event Routing DSL*. The runtime kernel remains ordered BEAM tuples consumed by =event-rules:route/2=. The =event-rules-dsl:routes= exported macro is now a compile-time source layer that expands accepted clauses to that same explicit rule data and rejects unsupported syntax. It intentionally introduces no runtime bindings; the regression suite contains a separate unsafe macro solely to demonstrate LFE's documented non-hygienic capture behavior.

** Project 2 -- Actor Application
:PROPERTIES:
:ID:       3b068142-3d00-5f2a-abe0-8f321c9817bb
:END:
Purpose: Build a useful raw-process service around Project 1 while keeping BEAM process/message semantics visible before OTP behaviours abstract them.
Learning outcomes: design explicit message protocols; distinguish PID identity from protocol vocabulary; correlate request/reply pairs with references; model actor state as recursive loop arguments; reason about selective receive, same-sender ordering, timeout, isolation, and observed failure; prove direct Erlang/LFE process interoperability.
Prerequisites: Chapters 1--7 and Project 1's pure routing kernel. Chapters 8--10 own the first executable process milestone.
Relevant chapters: Chapter 8 establishes the ordinary Erlang/LFE BEAM boundary and protocol terms; Chapter 9 derives process state and failure observation from recursive loops; Chapter 10 develops correlation, selective receive, ordering, timeout semantics, and protocol debugging. Later OTP chapters refactor the mechanism rather than redefining its semantics.
Architecture: one =actor-router= process owns the current immutable rule-list term and delegates routing to the independently tested =event-rules:route/2= kernel. Requests use =#(call CallerPid Ref Request)= and replies use =#(reply Ref Result)=. State changes only when the recursive loop receives a replacement rule term. No registry, process dictionary, ETS state, persistence layer, or hidden actor framework is introduced at this checkpoint.
Implementation language/tooling: LFE v2.2.2 compiled to BEAM under the same focused executable gate as Project 1, with a direct Erlang runtime smoke at the process boundary.
External dependencies: Project 1 code plus standard BEAM/LFE runtime facilities; no network service or third-party runtime dependency.
Tests: routing through the process, stale-reply correlation, rule-state replacement/readback, changed-state routing, tagged bad-request handling, same-sender ordered requests, caller-side timeout against a still-live silent process, clean stop, direct Erlang start/call/stop, and Erlang monitor observation of an intentionally crashed LFE actor.
Failure scenarios: stale reply, malformed request, wrong state recursion, caller timeout without remote cancellation, intentional actor crash, absent =DOWN= observation, and assumptions of global FIFO ordering across independent senders.
Visuals: editable actor protocol diagram showing caller/ref correlation, actor-owned state, pure Project 1 kernel delegation, and an independent monitor relationship.
Research requirements: current tagged LFE process syntax and current official Erlang process/signal/receive/monitor semantics, including selective-receive cost and ordering boundaries. OTP behaviours/supervision require a fresh later research pass.
Expected deliverable: runnable pre-OTP actor implementation, executable regressions, direct Erlang interoperability/failure smoke, research record, diagram, failure labs, and Chapters 8--10.
Current staged implementation: *Actor Router checkpoint A*. This is intentionally a raw-process teaching milestone. It does not claim =gen_server= callbacks, supervisor strategy, application layout, persistence, distribution, or release semantics.
